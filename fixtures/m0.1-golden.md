# M0.1 Golden Fixture

## Input

> I want an app where my partner and I can save places we want to visit.

## Expected behavior

The executable source of truth is `m0.1-golden.json`.

The compiler must resolve this into:

```yaml
goal: Keep a shared list of places two people want to visit.
app_type: shared_list
audience:
  kind: small_private_group
  size_hint: 2
primary_entity: place
actions:
  - add
  - edit
  - mark_visited
  - delete
device_priority: mobile
access:
  visibility: invite_only
  auth_required: true
persistence:
  required: true
open_questions: []
```

It must also preserve provenance:

### Explicit facts

- `partner` → small private group of two
- `places` → primary entity is `place`
- `save` → persistence is required

### Reversible assumptions

- shared-list product shape
- minimal lifecycle actions
- mobile-first presentation
- invite-only access for the known small group

The access default is intentionally privacy-preserving. The system can relax it later without asking the user to choose an authentication technology.

## Pass conditions

- No framework/database/hosting question is asked.
- User-stated facts and inferred defaults are distinguishable.
- The result validates against `schemas/intent.schema.json`.
- The output is sufficient for a planner to begin implementation.
- Low-risk reversible choices are defaults, not interruptions.
- The fixture passes with `npm run fixture`.
