# M0.2 Human Question Gate Fixture

The Question Gate exists to protect a non-engineer from two opposite failure modes:

1. **Question spam** — forwarding every engineering choice to the user.
2. **Silent overreach** — making privacy, spending, destructive, external, or product-defining decisions without consent.

## Gate order

```text
candidate decision
      ↓
implementation detail?
      ├─ yes, user did not request technical control → system resolves it
      ↓ no
consent required?
      ├─ yes → ask
      ↓ no
material to the outcome?
      ├─ no → choose a safe default
      ↓ yes
safe + reversible inference?
      ├─ yes → choose it and record the assumption
      ↓ no
does the user have the context to answer?
      ├─ no → system investigates first
      ↓ yes
ask in human language
```

## Required materialities

M0.2 covers:

- `privacy`
- `cost`
- `destructive`
- `external_action`
- `core_meaning`

It also proves that implementation details are suppressed by default.

## "Choose for me"

When an asked question has a safe non-destructive default, the question may expose `allow_choose_for_me: true` and `default_choice`.

This does **not** permit silent spending, silent publication, destructive actions, or external communication. Consent-required actions are still surfaced. "Choose for me" only gives the system permission to take the declared safe default for that question.

## Executable cases

The source of truth is `m0.2-question-gate.json`.

Run:

```bash
npm run fixture:m0.2
```

The fixture includes technical-choice suppression, privacy ambiguity, paid-service consent, destructive deletion, external sending, core product meaning, harmless visual defaults, and cases where the system must investigate before asking the user.
